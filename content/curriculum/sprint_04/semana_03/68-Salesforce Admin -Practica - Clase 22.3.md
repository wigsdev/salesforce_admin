¿Qué es APEX?

¿Qué es APEX?
Aspectos destacados del lenguaje Apex
Como ocurre con otros lenguajes de programación orientados a objetos, estos son algunos de los elementos de lenguaje que admite Apex:
Clases, interfaces, propiedades y colecciones (listas, mapas y conjuntos).
Notación de objetos y conjuntos.
Expresiones, variables y constantes.
Declaraciones condicionales (si..., entonces...) y declaraciones de flujo de control (bucles for y bucles while).

¿Qué es APEX?
A diferencia de otros lenguajes de programación orientados a objetos, Apex admite lo siguiente:
Desarrollo en la nube a medida que Apex se almacena, compila y ejecuta en la nube.
Desencadenadores, los cuales son similares a los desencadenadores de sistemas de base de datos.
Declaraciones de base de datos que permiten hacer llamadas directas a la base de datos y lenguajes de consulta para consultar y buscar datos.
Transacciones y reversiones.
El modificador de acceso global, que es más permisivo que el modificador public y permite el acceso a espacios de nombres y aplicaciones.
Control de versiones de código personalizado.
Además, no se aplica la distinción entre mayúsculas y minúsculas al lenguaje Apex.

Modificadores de Acceso
private:
Descripción: Indica que la clase, método o variable solo es accesible dentro de la misma clase.
Uso: Se utiliza para encapsular la lógica y proteger los datos de ser accedidos o modificados desde fuera de la clase.
private void myPrivateMethod() {
    // Lógica interna
}


Modificadores de Acceso
public:
Descripción: Permite que la clase, método o variable sea accesible desde cualquier otra clase dentro de la misma aplicación.
Uso: Se utiliza cuando se desea que otros componentes de la aplicación puedan acceder a la funcionalidad.
public void myPublicMethod() {
    // Lógica accesible desde otras clases
}



Modificadores de Acceso
global:
Descripción: Permite que la clase, método o variable sea accesible desde cualquier lugar, incluso desde paquetes externos.
Uso: Se utiliza principalmente para clases y métodos que se desean exponer a otros desarrolladores o aplicaciones que puedan estar utilizando tu código.
global class MyGlobalClass {
    global void myGlobalMethod() {
        // Lógica accesible globalmente
    }
}

RETO:
Crear una clase de Apex que devuelva cuentas
Cree una clase de Apex que devuelva una lista de objetos Account para un estado de usuario especificado.
Cree una clase de Apex que contenga un método estático:
Nombre: AccountUtils
Nombre del método: accountsByState
El método debe devolver el ID y el nombre de todos los objetos Account que coincidan con BillingState para la abreviatura del estado pasado al método

RETO
public class AccountUtils {
    // Método estático que devuelve una lista de cuentas por estado
    public static List<Account> accountsByState(String stateAbbreviation) {
        // Verificar que la abreviatura del estado no esté vacía
        if (String.isEmpty(stateAbbreviation)) {
            return new List<Account>(); // Retornar lista vacía si no se proporciona un estado
        }

        // Consulta SOQL para obtener cuentas que coincidan con el estado de facturación
        List<Account> accounts = [SELECT Id, Name FROM Account WHERE BillingState = :stateAbbreviation];     
        return accounts; // Retornar la lista de cuentas
    }
}

RETO:
Explicación del Código:
Clase AccountUtils: Esta es la clase que contiene el método estático.
Método accountsByState:
Parámetro: Acepta una cadena stateAbbreviation que representa la abreviatura del estado.
Validación: Verifica si la abreviatura del estado está vacía y, si es así, devuelve una lista vacía.
Consulta SOQL: Realiza una consulta para obtener todos los registros de Account donde el campo BillingState coincide con la abreviatura del estado proporcionada.
Retorno: Devuelve la lista de cuentas que cumplen con el criterio.

RETO:
Ejemplo de Uso:
Para utilizar este método, puedes llamarlo desde la consola anónima o desde otro contexto en Apex, como se muestra a continuación:
List<Account> accountsInCalifornia = AccountUtils.accountsByState('CA');
for (Account acc : accountsInCalifornia) {
    System.debug('Account ID: ' + acc.Id + ', Account Name: ' + acc.Name);
}
Este código llamará al método accountsByState con la abreviatura 'CA' (California) y luego imprimirá el ID y el nombre de cada cuenta que coincida.

UTILIZAR sObjects
Dado que Apex está perfectamente integrado con la base de datos, puede acceder a los registros de Salesforce y sus campos directamente desde Apex. 
Cada registro de Salesforce se representa de forma nativa como un sObject en Apex. 

Por ejemplo, el registro de cuenta Acme se corresponde con un sObject de cuenta en Apex. Los campos del registro Acme que puede ver y modificar en la interfaz de usuario se pueden leer y modificar además directamente en el sObject.

UTILIZAR sObjects
Nombres de sObjects y campos
Apex hace referencia a sObjects estándar o personalizados y los campos tienen nombres de API exclusivos.
Los nombres de objetos y campos de la API pueden variar con respecto a sus etiquetas. Por ejemplo, el campo Employees tiene la etiqueta Employees y se muestra en la página del registro de cuenta como Employees, pero su nombre en la API es NumberOfEmployees. Para acceder a este campo en Apex, debe usar el nombre del campo de la API: NumberOfEmployees.
En el caso de los objetos y campos personalizados, el nombre de la API siempre termina por el sufijo __c. En el caso de los campos de relación personalizados, el nombre de la API termina por el sufijo __r. Por ejemplo:
Un objeto personalizado con la etiqueta Merchandise tiene el nombre Merchandise__c en la API.
Un objeto personalizado con la etiqueta Description tiene el nombre Description__c en la API.
Un campo de relación personalizado con la etiqueta Items tiene el nombre Items__r en la API.

Creación de sObjects y campos
Para poder insertar un registro de Salesforce, debe crearlo en la memoria primero como un sObject. Como ocurre con cualquier otro objeto, los sObjects se crean con el operador new:
Account acct = new Account();
El nombre de objeto de la API se convierte en el tipo de datos de la variable de sObject en Apex. En este ejemplo, Account es el tipo de datos de la variable acct.
La cuenta a la que hace referencia la variable acct está vacía porque no hemos completado aún ningún campo. Se pueden agregar campos de dos formas: mediante el constructor o mediante la notación de puntos.
La forma más rápida de agregar campos es especificarlos como pares de nombre-valor en el constructor. Por ejemplo, esta declaración crea un sObject de cuenta y completa el campo Name con un valor de cadena.
Account acct = new Account(Name='Acme');

Creación de sObjects y campos
El campo Name es el único campo obligatorio para las cuentas, lo que significa que se debe completar para poder insertar un registro nuevo. Sin embargo, también puede completar otros campos para el registro nuevo. En este ejemplo se agregan un número de teléfono y el número de empleados.
Account acct = new Account(Name='Acme', Phone='(415)555-1212', NumberOfEmployees=100);
De forma alternativa, puede usar la notación de puntos para agregar campos a un sObject. Lo siguiente equivale al ejemplo anterior, pero se han agregado algunas líneas de código.
Account acct = new Account(); 
acct.Name = 'Acme'; 
acct.Phone = '(415)555-1212'; 
acct.NumberOfEmployees = 100;

Manipular registros con DML
El lenguaje de manipulación de datos (DML) en Apex permite gestionar registros en Salesforce mediante declaraciones simples. 
Facilita operaciones como insertar, actualizar y eliminar registros directamente en la plataforma Lightning.

Reto: 
Create a method for inserting accounts.
Para superar este reto, cree una clase Apex que inserte una nueva cuenta con el nombre de un parámetro entrante. Si la cuenta se inserta correctamente, el método debe devolver el registro de la cuenta. Si se produce una excepción DML, el método debe devolver null.
The Apex class must be called AccountHandler and be in the public scope
The Apex class must have a public static method called insertNewAccount
The method must accept an incoming string as a parameter, which will be used to create the Account name
The method must insert the account into the system and then return the record
The method must also accept an empty string, catch the failed DML and then return null

public class AccountHandler {
    public static Account insertNewAccount(String accountName) {
        if (String.isEmpty(accountName)) {
            return null;
        }
        
        Account newAccount = new Account(Name = accountName);

            return newAccount;

CONSULTAS SOQL
Para leer registros en Salesforce, se utiliza el lenguaje de consulta de objetos (SOQL), similar al SQL estándar pero adaptado a la Plataforma Lightning. Apex permite insertar consultas SOQL directamente en el código, facilitando la obtención de resultados. Las consultas se incluyen entre corchetes y se asignan a un conjunto de sObjects.
Account[] accts = [SELECT Name,Phone FROM Account];

Sintáxis básica
SELECT fields FROM ObjectName [WHERE Condition]
La cláusula WHERE es opcional. Vamos a empezar con una consulta muy sencilla. Por ejemplo, la consulta siguiente recupera cuentas y obtiene los campos Nombre y Teléfono para cada cuenta.
SELECT Name,Phone FROM Account
La consulta consta de dos partes:
SELECT Name,Phone: en esta parte se incluyen los campos que desea recuperar. Los campos se especifican después de la palabra clave SELECT en una lista delimitada por comas. También puede especificar un solo campo, en cuyo caso no es necesario el uso de comas (por ejemplo, SELECT Phone).
FROM Account: en esta parte se especifica el objeto estándar o personalizado que desea recuperar. En este ejemplo, es Account. En el caso de un objeto personalizado llamado Invoice_Statement, es Invoice_Statement__c.

OPCIONES de consulta
1. Consulta Básica
SELECT Field1, Field2 FROM ObjectName
2. Consulta con Filtros (WHERE)
SELECT Field1, Field2 FROM ObjectName WHERE Condition
3. Consulta con Ordenamiento (ORDER BY)
SELECT Field1, Field2 FROM ObjectName ORDER BY Field1 ASC|DESC
4. Consulta con Límite (LIMIT)
SELECT Field1, Field2 FROM ObjectName LIMIT Number
5. Consulta con Agrupamiento (GROUP BY)
SELECT Field1, COUNT(Id) FROM ObjectName GROUP BY Field1
6. Consulta con Filtros de Agrupamiento (HAVING)
SELECT Field1, COUNT(Id) FROM ObjectName GROUP BY Field1 HAVING COUNT(Id) > Number

7. Consulta con Subconsultas
SELECT Field1 FROM ObjectName WHERE Id IN (SELECT ObjectId FROM RelatedObject)
8. Consulta de Campos Relacionados
SELECT Field1, RelatedObject.Field2 FROM ObjectName
9. Consulta con Funciones de Agregación
SELECT COUNT(Id), MAX(Field1) FROM ObjectName

Reto
Cree una clase Apex que devuelva contactos basándose en parámetros entrantes.
Para este reto, tendrá que crear una clase que tenga un método que acepte dos cadenas. El método busca contactos que tengan un apellido que coincida con la primera cadena y un código postal que coincida con la segunda. Obtiene el ID y el Nombre de esos contactos y los devuelve.

The Apex class must be called ContactSearch and be in the public scope
The Apex class must have a public static method called searchForContacts
The method must accept two incoming strings as parameters
The method should then find any contact that has a last name matching the first string, and mailing postal code (API name: MailingPostalCode) matching the second string
The method should finally return a list of Contact records of type List that includes the ID and Name fields


Reto
public class ContactSearch {
    public static List<Contact> searchForContacts(String lastName, String postalCode) {
        return [SELECT Id, Name FROM Contact WHERE LastName = :lastName AND MailingPostalCode = :postalCode];
    }
}
List<Contact> results = ContactSearch.searchForContacts('ApellidoEjemplo', 'CodigoPostalEjemplo');
System.debug(results);
